# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## О проекте

kogda-igra.ru — календарь ролевых игр (LARP). Сайт существует как PHP-приложение; этот репозиторий —
порт на ASP.NET Core 10.

Стратегия порта — «1=1»: сначала буквально повторить существующее поведение, идиоматичная
архитектура потом. Основание — [docs/adr001-repo-and-testing-strategy.md](docs/adr001-repo-and-testing-strategy.md).

Сейчас в репозитории есть только compat-харнесс (`src/KogdaIgra.CompatTests`). Портала ещё нет.

## Где исходник

Оригинал на PHP лежит в **соседнем чекауте** `..\kogda-igra`. Это источник истины по поведению:
сверяться с ним при портировании обязательно.

**Из этого репозитория PHP-репозиторий НИКОГДА не модифицируется.** Ни правок кода, ни коммитов,
ни `git` команд, меняющих его состояние. Только чтение и `docker compose build` для локальной сборки образа.

## Команды

```bash
dotnet build
dotnet format                                       # Применить стиль кода (обязательно перед коммитом)
dotnet format --verify-no-changes --severity warn   # Проверка, ровно такая же в CI (.github/workflows/build.yml)
dotnet test                                         # Все тесты
```

Прогон тестов требует только поднятого Docker: образ PHP-версии публичный (см. ниже).

## Тесты

**Главное правило**: тест пишется **против PHP-версии**, зеленеет на ней, и только потом под него
пишется код на .NET. Тест — это зафиксированный контракт текущего поведения, а не описание желаемого.

Если тест невозможно прогнать против PHP-версии — это повод остановиться и подумать, а не повод
написать тест «только для .NET». Скорее всего, либо тест проверяет не то, либо харнесс чего-то не умеет.

- Тестовый фреймворк — **TUnit** на Microsoft.Testing.Platform, см.
  [docs/adr002-test-stack.md](docs/adr002-test-stack.md). Это сознательно не xUnit, как в joinrpg-net;
  API другой, по памяти из joinrpg писать нельзя.
- MTP-режим включается секцией `"test"` в [global.json](global.json). Не в `dotnet.config` — этот
  вариант пробовали, он не работает.
- Фикстура сайта — `[ClassDataSource<PhpSiteUnderTest>(Shared = SharedType.PerTestSession)]`,
  сама фикстура реализует `IAsyncInitializer` + `IAsyncDisposable`.
- Динамический пропуск — `Skip.When(condition, reason)`. Им же тесты пропускаются, когда Docker
  или образ недоступны (`PhpSiteUnderTest.StartupFailure`).
- **Моки запрещены** — ни Moq, ни NSubstitute. Compat-тест проверяет реальный ответ реального сайта;
  внешние интеграции глушатся отсутствием ключей в окружении контейнера, а не подменой типов.
- **Готча, проверено экспериментально**: PHP-приложение отдаёт **HTTP 200 даже при сломанной БД** —
  в теле тогда лежит сырой текст ошибки Postgres. Ассерт, опирающийся только на статус-код, ничего
  не проверяет. Использовать `SiteResponse.ContainsDatabaseError` / `SiteResponse.LooksLikeHtmlPage`.
- Образ PHP-версии — `ghcr.io/joinrpg/kogda-igra:latest`. Пакет **публичный**, тянется анонимно,
  ничего настраивать не надо. Подменить образ (например, на локально собранный из соседнего
  чекаута) можно переменной `KOGDA_IGRA_IMAGE` — см. [docs/compat-tests.md](docs/compat-tests.md).
  Внимание: владелец образа — организация `joinrpg`, а не `leotsarev`.

## Правила кода

- **Без regex** — по возможности избегать регулярных выражений.
- **Язык UI**: все видимые пользователю строки — всегда на русском языке.
- **MSBuild**: общие свойства (`TargetFramework`, `Nullable`, `TreatWarningsAsErrors` и т.п.) живут
  только в [Directory.Build.props](Directory.Build.props). В `.csproj` их не дублировать. Версии
  пакетов — централизованно в [Directory.Packages.props](Directory.Packages.props), в `PackageReference`
  версия не пишется.
- **Версия .NET SDK**: не обновлять вручную в `global.json`. Там `"rollForward": "latestFeature"` —
  SDK сам подхватывает последнюю feature-версию. Dependabot обновляет только NuGet-пакеты, это нормально.

## Фикс багов

При исправлении бага **всегда рассматривать добавление теста**, который воспроизводит баг до фикса и
проходит после. Для порта это в первую очередь compat-тест: сначала проверить, как ведёт себя
PHP-оригинал, и зафиксировать именно его поведение.
