# Построчное покрытие PHP-версии

Замер показывает, какие строки оригинала выполняются во время прогона compat-тестов.
Для порта «1=1» это важнее процента как такового: невыполненная ветка легко переносится
с изменённым поведением, и заметить это будет некому.

**PHP-репозиторий при этом не изменяется.** Образ с Xdebug собирается поверх
опубликованного, всё нужное лежит здесь.

## Как снять

```bash
# 1. Собрать образ с Xdebug (один раз, пока не обновится оригинал)
docker build -t kogda-igra-coverage:latest coverage/

# 2. Прогнать тесты против него, складывая сырые данные
KOGDA_IGRA_IMAGE=kogda-igra-coverage:latest \
COMPAT_COVERAGE_DIR=./artifacts/coverage-data \
dotnet test
```

```powershell
# 3. Собрать отчёт
./coverage/report.ps1 -DataDirectory ./artifacts/coverage-data `
                      -SourceDirectory ../kogda-igra/public_html
```

Скрипт печатает сводку, список наименее покрытых файлов и пишет `coverage/lcov.info`
для внешних инструментов.

Без `COMPAT_COVERAGE_DIR` харнесс работает как обычно — на повседневный прогон замер
не влияет.

## Как устроено

`coverage/Dockerfile` ставит Xdebug поверх `ghcr.io/joinrpg/kogda-igra:latest` и
прописывает `auto_prepend_file=/coverage-collect.php`. Этот файл (`coverage/collect.php`)
включает сбор на каждый запрос и в обработчике завершения сбрасывает результат в
`/coverage-data` — по файлу на запрос, с уникальным именем, потому что запросы могут
идти параллельно.

Харнесс подключает каталог с хоста внутрь контейнера, если задана `COMPAT_COVERAGE_DIR`
(см. `PhpSiteUnderTest`). Дампы переживают остановку контейнера.

### Обязательные флаги

```php
xdebug_start_code_coverage(XDEBUG_CC_UNUSED | XDEBUG_CC_DEAD_CODE);
```

Без `XDEBUG_CC_UNUSED` Xdebug возвращает **только выполненные** строки, и отчёт выходит
ровно стопроцентным при любом наборе тестов. На этом легко обмануться: первый замер
здесь показал «100% в 77 файлах», и цифра была бессмысленной.

`XDEBUG_CC_DEAD_CODE` помечает недостижимые строки статусом `-2`; в знаменатель они
не идут.

## Что показывают цифры

На 176 тестах: **2551 строка из 3470 (73.5%) в 77 файлах**, плюс 18 файлов, которые
не подключались ни разу.

Важная оговорка: файлы, не подключённые ни разу, в проценте **не участвуют** — Xdebug
про них ничего не знает. Поэтому скрипт выводит их отдельным списком, иначе картина
выглядела бы лучше, чем есть. Ради этого и нужен `-SourceDirectory`.

Наименее покрытые файлы по последнему замеру и причины:

| Файл | Покрытие | Почему |
|---|---|---|
| `appcode/best_calendar.php` | 7% | Блок «самая популярная игра» требует `vk_likes > 0`, а во всех фикстурах он нулевой |
| `appcode/media.php` | 15% | Фото сломаны целиком ([#75](https://github.com/joinrpg/kogda-igra/issues/75)) |
| `appcode/logic/photo.php` | 19% | То же |
| `appcode/logic/review.php` | 18% | Покрыт только просмотр; добавление и удаление отзывов — нет |
| `edit/merge/index.php` | 29% | Слияние падает на любых параметрах ([#76](https://github.com/joinrpg/kogda-igra/issues/76)) |
| `api/allrpg-info/find-by-id.php` | 33% | Эндпоинт мёртв ([#74](https://github.com/joinrpg/kogda-igra/issues/74)) |
| `archive/index.php` | 44% | Страница обрывается на fatal ([#69](https://github.com/joinrpg/kogda-igra/issues/69)) |

То есть низкое покрытие здесь в основном честно отражает сломанные разделы, а не
пробелы в тестах. Единственный явный пробел — `best_calendar.php`: достаточно завести
игру с ненулевым `vk_likes`.

## Ограничения

- Замер построчный, не по ветвлениям: строка с `&&` считается покрытой, даже если
  второй операнд никогда не вычислялся.
- Файлы, не подключённые ни разу, в проценте не учитываются (см. выше).
- Образ надо пересобирать после обновления оригинала, иначе замер идёт по старому коду.
