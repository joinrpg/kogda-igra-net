# Покрытие точек входа PHP-версии

Таблица показывает, какие страницы и эндпоинты оригинала уже закреплены compat-тестами,
а какие нет. Это основной ориентир: **портировать раздел, у которого нет зелёного
compat-теста, — значит портировать вслепую.**

Точки входа перечислены по файлам `*.php` в `public_html/` PHP-репозитория, исключая
`appcode/` и `common/` (это библиотеки, а не страницы).

Считано на 162 тестах. Покрыто **37 из 56** точек входа (66%).

## Как это измерялось

Список точек входа — перечисление файлов; отметки о покрытии — сопоставление с адресами,
которые реально запрашивают тесты. Это **покрытие по эндпоинтам, а не по строкам**: оно
не говорит, сколько ветвлений внутри страницы проверено.

## Построчное покрытие PHP: как его можно получить

Править PHP-репозиторий для этого **не нужно**. Образ с Xdebug собирается поверх
опубликованного, целиком в этом репозитории:

```dockerfile
FROM ghcr.io/joinrpg/kogda-igra:latest
RUN pecl install xdebug && docker-php-ext-enable xdebug
```

Проверено: Xdebug 3.5.3 встаёт без единой правки в оригинале, `xdebug_start_code_coverage()`
в режиме `XDEBUG_MODE=coverage` работает. Харнесс уже умеет брать произвольный образ через
`KOGDA_IGRA_IMAGE`, так что подменить его — вопрос одной переменной.

Чего не хватает для полной картины:

1. `auto_prepend_file`, который включает сбор покрытия на каждый запрос, и обработчик
   завершения, сбрасывающий результат в файл.
2. Слияния дампов со всех запросов прогона.
3. Отчёта — например, в формате Clover или lcov, чтобы читать глазами и сравнивать
   между прогонами.

Оценка: половина дня работы. Ценность — видно, какие ветвления внутри страницы тесты
не трогают, а не только какие страницы открывались. Для порта «1=1» это существенно:
непокрытая ветка легко переносится с изменённым поведением, и никто этого не заметит.
