# ADR 0002: Тестовый стек — TUnit на Microsoft.Testing.Platform

## Статус

Принято

## Контекст

По [ADR 0001](adr001-repo-and-testing-strategy.md) весь смысл этого репозитория на первом этапе —
один тестовый проект, который гоняет PHP-версию как чёрный ящик, а позже без переписывания
переключается на .NET-реализацию. То есть тестовый фреймворк здесь не деталь, а основной инструмент.

Репозиторий новый (greenfield), целевой рантайм — .NET 10, унаследованных тестов нет. Требования
к фреймворку определяются устройством харнесса:

- **Фикстура на весь прогон.** Поднять docker-сеть, Postgres и контейнер с PHP-сайтом — дорого
  (десятки секунд). Это должно происходить ровно один раз на сессию тестов, с асинхронной
  инициализацией и асинхронной очисткой: контейнеры поднимаются и гасятся только `await`-ом.
- **Дешёвый динамический пропуск.** Docker может быть не запущен, образ PHP-версии может быть
  недоступен (см. [compat-tests.md](compat-tests.md)). В этом случае тесты должны
  пропускаться с внятной причиной прямо в теле теста — условие известно только после попытки
  поднять контейнер, то есть на этапе атрибутов его не выразить.
- **Асинхронность из коробки**, включая ассерты: весь харнесс — HTTP и Npgsql.

Отдельно стоял вопрос согласованности с соседним проектом того же автора, joinrpg-net, где
используется xUnit v2 + Shouldly.

## Решение

**TUnit** (`Directory.Packages.props`) поверх **Microsoft.Testing.Platform (MTP)**.

MTP-режим включается секцией в [`global.json`](../global.json):

```json
"test": {
  "runner": "Microsoft.Testing.Platform"
}
```

Вариант с `dotnet.config` пробовали — он **не работает**, `dotnet test` продолжает уходить в VSTest.

Аргументы платформы тестирования передаются после `--`. Отчёты дополнительных пакетов не требуют:
TUnit сам пишет HTML-отчёт в каталог результатов, а в GitHub Actions — ещё и сводку прогона
в summary job'а (`GITHUB_STEP_SUMMARY`).

Из возможностей TUnit харнесс использует:

- `[ClassDataSource<PhpSiteUnderTest>(Shared = SharedType.PerTestSession)]` — фикстура сайта,
  один экземпляр на весь прогон, инжектится в конструктор тестового класса;
- `IAsyncInitializer` + `IAsyncDisposable` на фикстуре — асинхронный старт и остановка контейнеров
  без `.GetAwaiter().GetResult()`;
- `Skip.When(condition, reason)` — пропуск по результату попытки старта (локально; в CI фикстура
  вместо этого бросает исключение из `InitializeAsync`, и TUnit роняет зависящие от неё тесты);
- `await Assert.That(...)` — встроенные асинхронные ассерты, отдельная библиотека ассертов не нужна.

## Альтернативы и почему отклонены

- **xUnit v2 + Shouldly + Xunit.SkippableFact — как в joinrpg-net.** Главный аргумент «за» —
  единообразие с соседним проектом: один и тот же автор, одни и те же привычки, переносимые
  сниппеты. Отклонено: session-scoped фикстура в xUnit v2 — это `ICollectionFixture` плюс
  `IAsyncLifetime` плюс объявление коллекции, заметно многословнее; асинхронный `IAsyncLifetime`
  в v2 неполноценен; динамический пропуск требует стороннего пакета `Xunit.SkippableFact`, который
  живёт своей жизнью относительно версий xUnit. Для репозитория без унаследованного кода цена
  единообразия оказалась выше выгоды.
- **xUnit v3.** Чинит часть претензий к v2 (нормальная асинхронность, встроенный пропуск) и умеет
  MTP. Отклонено: на момент решения это миграционный, ещё не устоявшийся стек, а преимуществ перед
  TUnit для нашего сценария он не даёт — при этом ни привычности v2, ни лаконичности TUnit.

## Последствия

- Минус: API незнаком относительно joinrpg-net. Писать тесты «по памяти из joinrpg» нельзя, это
  прямо зафиксировано в [CLAUDE.md](../CLAUDE.md).
- Минус: раннер — MTP, а не VSTest. Аргументы идут после `--`, часть привычных ключей `dotnet test`
  не применима, поведение IDE может отличаться.
- Минус: `coverlet.collector` (VSTest-collector) в этом режиме не используется. Покрытие, если оно
  понадобится, потребует `Microsoft.Testing.Extensions.CodeCoverage`.
- Минус: `global.json` теперь несёт не только версию SDK, но и секцию `test`. Это неочевидное место,
  его легко потерять при правке файла.
- Плюс: фикстура контейнеров описывается одним атрибутом и двумя интерфейсами, без служебных
  коллекций и обёрток.
- Плюс: пропуск по недоступности Docker/образа — одна строка в тесте, без сторонних пакетов.
